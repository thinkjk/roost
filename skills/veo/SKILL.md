# Veo video generation

`veo.sh` (next to this file) sends a prompt to Veo through the same LiteLLM
gateway Claude uses, waits for the result and saves an MP4. It prints the
saved path.

```bash
~/.claude/skills/veo/veo.sh -o assets/clip.mp4 "prompt"      # Claude Code
~/.agents/skills/veo/veo.sh -o assets/clip.mp4 "prompt"      # Codex / opencode
```

| Flag | Values | Default |
|---|---|---|
| `-m` | `veo-3.1-fast-generate-001` (cheaper, quick drafts), `veo-3.1-generate-001` (best quality) | fast |
| `-s` | seconds: `4`, `6` or `8` (Veo supports nothing else) | `4` |
| `-r` | `1280x720` (landscape), `720x1280` (portrait), `1920x1080` (needs `-s 8`) | `1280x720` |
| `-o` | output path | `veo-<timestamp>.mp4` in the current folder |

## Rules

- **Every run costs real money**, billed per second of video (roughly tens of
  cents per second; standard costs a few times more than fast). Before each
  generation, tell the user the model, length and resolution and get a yes.
  Never loop, retry blindly, or generate variations without asking.
- Draft with fast and 4 seconds; switch to standard, 8 seconds or 1080p only
  when the user wants the final version.
- Generation takes about 1-3 minutes. Run it once and wait; do not start
  another while one is running.
- Videos usually include generated audio. Describe the sound you want (or
  "no music, ambient sound only") in the prompt.

## Writing the prompt

Veo follows concrete, visual prompts best. Cover, in one or two sentences:
subject and action, setting, camera (e.g. "slow dolly-in", "static wide
shot", "handheld"), lighting and style ("golden hour", "flat 2D animation",
"product shot on white"), and sound. Avoid text-in-video requests: Veo
renders on-screen text poorly.

## When it fails

- `request refused: ...` with a model error: the model name is wrong or not
  enabled on the Google Cloud project. Only the two models above are known
  to work here.
- `failed: Unsupported output video duration`: use 4, 6 or 8.
- `no gateway`: roost's Claude gateway settings are missing; ask the user.
- Policy rejections (people, brands, unsafe content) come back as `failed`
  with Google's reason; rephrase only with the user's agreement.
